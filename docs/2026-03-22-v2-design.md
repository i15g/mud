# mud v2 Design

## Overview

mud is a Go CLI that sanitizes filenames to URL-friendly format. v2 adds richer sanitize rules,
an ignore-pattern system, stdin support, multi-file handling, interactive mode, and a full CLI UX
overhaul.

## Architecture

Four files, same package:

`runRename` and `runRecursive` take a `renameOpts` struct (replacing the current `dryRun, quiet
bool` parameters) to carry the growing flag set cleanly: `dryRun`, `quiet`, `verbose`,
`interactive`, `force`.

| File             | Responsibility                                                     |
| ---------------- | ------------------------------------------------------------------ |
| `main.go`        | pflag parsing, stdin detection, mode dispatch, multi-arg iteration |
| `sanitize.go`    | `Sanitize()` — pure string transformation pipeline                 |
| `rename.go`      | `runRename()`, `runRecursive()`, interactive prompt                |
| `ignore.go`      | `ShouldIgnore()` — hard-coded ignore predicates (new)              |
| `ignore_test.go` | Tests for `ShouldIgnore()` (new)                                   |

New dependency: `github.com/spf13/pflag` only. Accent normalization deferred to v3.

## Sanitize Pipeline

`Sanitize()` processes a name through these steps in order:

0. **URL-decode** (`net/url` stdlib): `%20` → space, `%28`/`%29` → parens, etc. URL-decoding
   is pipeline-internal; `ShouldIgnore` always receives the raw filesystem basename (pre-decode).
1. **Preserve leading dots** — leading dots are always stripped temporarily and restored at the
   end. Whether a dotfile ever reaches `Sanitize()` is controlled by `ShouldIgnore` and
   `-f/--force`, not by this step.
2. **Extract up to 2 trailing extensions**: dot-counting and extension splitting are applied to
   the name _after_ leading dots are stripped in step 1. If the remaining name contains 2 or more
   dots, take the last two dot-segments as the extension (e.g. `foo.tar.gz` → stem `foo`, ext
   `.tar.gz`; `.foo.tar.gz` → after step 1 strips `.`, remaining `foo.tar.gz` → stem `foo`, ext
   `.tar.gz`); if only one dot, take one (e.g. `foo.txt` → stem `foo`, ext `.txt`). Predicate 2
   in `ShouldIgnore` uses `filepath.Ext` (single extension only) for simplicity — the 2-extension
   rule applies only inside `Sanitize`.
3. **Strip leading underscores from stem** (preserved, restored at end). If stripping leaves an
   empty stem (e.g. `_.txt`), leading underscores are still restored over an empty body:
   `_.txt → _.txt`.
4. **Lowercase stem**
5. **Special replacements**: `@` → `-at-`, `&` → `-and-`
6. **Replace separators with hyphens**: space, `\n`, `_`, `,`, `+`, `.` (interior periods in
   stem), `—`, `–`, `;`, `:`, `(`, `)`, `{`, `}`, `[`, `]`, `|`
7. **Collapse 3+ hyphens → 2**
8. **Remove chars not in `[a-z0-9\-]`** (no periods allowed in stem after step 6)
9. **Trim leading/trailing hyphens**
10. **Lowercase extension**

### Examples

```
foo.tar.gz            →  foo.tar.gz
My.Config.File.txt    →  my-config.file.txt
hello%20world.txt     →  hello-world.txt
foo@bar               →  foo-at-bar
@foo.txt              →  at-foo.txt      (leading hyphen from @→-at- trimmed at step 9)
a&b                   →  a-and-b
foo(bar).txt          →  foo-bar.txt
foo[1].txt            →  foo-1.txt
```

Accent normalization (e.g. `é` → `e`) is deferred to v3. Accented chars continue to be stripped
at step 8.

## Ignore Patterns

New `ignore.go` exports `ShouldIgnore(name string) bool`. All rules are bypassed by `-f/--force`.
`ShouldIgnore` operates on the basename only.

Four predicates (all must be false to proceed with rename):

1. **Dotfiles**: `strings.HasPrefix(name, ".")` — this includes `._foo` (macOS resource fork
   files), which also start with `.`
2. **All-caps stems**: stem (name without extension, via `filepath.Ext`) matches `^[A-Z]+$` —
   catches `README.md`, `LICENSE`, `CONTRIBUTING`, `CHANGELOG`, etc. Names with hyphens, digits,
   or other non-alpha chars in an all-caps stem (e.g. `RELEASE-NOTES`) are intentionally _not_
   protected by this predicate.
3. **Known filenames**: exact match against `Thumbs.db`, `desktop.ini`, `ehthumbs.db`,
   `Makefile`
4. **Convention extensions** — extensions where mud would break language/toolchain conventions:
   - snake_case languages: `.go`, `.py`, `.rs`, `.rb`, `.c`, `.h`, `.cpp`, `.hpp`, `.ex`, `.exs`,
     `.erl`
   - PascalCase languages: `.java`, `.scala`, `.kt`, `.cs`, `.swift`

## CLI / UX

### Flags

Migrated from custom parser to `github.com/spf13/pflag` (POSIX-compliant, combined short flags
like `-rd`, auto-generated help via `PrintDefaults()`).

| Flag                | Notes                                                           |
| ------------------- | --------------------------------------------------------------- |
| `-n, --dry-run`     | Renamed from `-d` (breaking change)                             |
| `-q, --quiet`       | Now means print nothing (was: print new path) (breaking change) |
| `-v, --verbose`     | New — prints `old -> new`                                       |
| `-i, --interactive` | New — y/n/q prompt per file before rename                       |
| `-f, --force`       | New — bypass all ignore patterns                                |
| `-r, --recursive`   | Unchanged                                                       |
| `-t, --text`        | Dropped — replaced by automatic stdin detection                 |
| `-h, --help`        | Unchanged                                                       |

### Output Modes (breaking change)

| Mode           | Output            |
| -------------- | ----------------- |
| default        | new filename only |
| `-q/--quiet`   | nothing           |
| `-v/--verbose` | `old -> new`      |

Previously default was `old -> new` and `-q` printed the new path. The new default is better for
scripting: `NEW=$(mud FOO.txt)`.

"Already clean" filenames (input == output after sanitize) in rename mode: default mode prints the
(unchanged) name (ensuring `NEW=$(mud already-clean.txt)` still captures the name); verbose mode
skips silently (nothing changed, nothing to show); quiet mode prints nothing.

### stdin Detection

If `os.Stdin` is not a tty (`fi.Mode()&os.ModeCharDevice == 0`) and no positional args are
present, mud reads all of stdin, treats it as a single string (newlines become hyphens via the
normal pipeline), and prints the sanitized result. If positional args are present, stdin mode is
suppressed and args are processed normally. If `-r` is present, recursive mode takes priority over
stdin detection regardless of TTY state. This replaces the former `-t/--text` flag.

```
echo "My File Name" | mud       →  my-file-name
printf "foo\nbar" | mud         →  foo-bar
```

### Multiple Positional Args

`mud FOO.txt BAR.txt` iterates all args. Shell handles glob expansion; mud accepts whatever args
the shell passes.

Errors are reported per-file; processing continues on failure (non-zero exit at end if any error
occurred).

### Interactive Mode (`-i`)

Before each rename, mud prompts:

```
rename FOO.txt → foo.txt? [y/n/q]
```

- `y` — rename this file
- `n` — skip this file
- `q` — skip this file and abort all remaining files

If stdin is not a TTY when `-i` is used, mud exits with an error: `-i requires an interactive
terminal`. Interactive mode applies per-file in recursive mode as well. When combined with `-f`,
force bypasses ignore patterns but the interactive prompt still applies.

### Dry-run Output (breaking change)

Dry-run always prints `old -> new (dry run)` on one line, regardless of `-q`/`-v` flags — quiet
is not meaningful when the purpose is to preview changes. `-nv` produces the same format as `-n`
alone. The v1 format was two lines (`old --> new\n(dry run)\n`); v2 uses one line with `->`.

### Exit Codes

- Clobber error (target exists, different file): non-zero
- File-not-found or rename failure: non-zero; processing continues for remaining args
- Interactive quit (`q`): exits zero (user intentionally stopped)
- Non-zero exit if _any_ error occurred across all args

### Error on Clobber (breaking change)

If the target already exists and is a different file, mud now returns an error (was: silent skip).
Error format: `mud: <input>: target already exists: <output>`. Case-only renames on
case-insensitive filesystems (e.g. `FOO` → `foo`) are still allowed via the existing
`os.SameFile` check.

Note: `TestRunRename_NoClobber` in `rename_test.go` encodes the old silent-skip behavior and must
be updated to assert an error is returned.

### Recursive Mode

`runRecursive` already processes bottom-up correctly when given a path. The v1 quirk (running from
within the target directory) was a UX/docs issue, not a code bug — no code change needed.
